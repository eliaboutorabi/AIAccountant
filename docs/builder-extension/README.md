# From foundations to application engineering

The extension adds ten connected chapters after the 25-module foundation course. Its purpose is to make a learner able to inspect, implement, test and explain a document-processing application, an evidence-linked analytical interface, and a multimodal tool-using assistant. The teaching uses original fictional cases and primary technical references; it does not describe or reproduce a particular portfolio application.

The design was informed by source-level architecture review, not feature descriptions alone. Claimed behavior and implemented behavior were separated during research. Private review notes remain outside the published repository; no reference application code, artwork, branding or data is included.

## Learning structure

The five foundation days remain intact. Days six and seven each budget 330 minutes of study/practice plus 30 minutes of cumulative review. The resulting 42 planned hours are authoring estimates, not measured completion times. Independent builds and specialist practice take additional time. The course does not certify mastery of an entire profession through a quiz score.

## Practice contracts

Five workbenches execute local calculations or explicit state machines. They do not claim to perform hosted OCR, provider inference or microphone streaming. OCR readings, provider measurements and model proposals are authored fixtures so that failures can be reproduced and their consequences inspected. The existing neural-network, transformer, adaptation and denoising labs continue to train actual models.

Each new chapter includes six explained knowledge checks, one distinct transfer case, a written assignment with a worked solution, an interview defense, glossary support, one original generated illustration and two native teaching diagrams. The application’s progress, search, visual atlas, downloads and interview navigation include the extension while preserving earlier learning records.

## Review and release

Final educational review, executed test counts and public deployment checks are recorded in `release-review.md` after validation. Image prompts are recorded in [image-prompts.md](image-prompts.md). Engineering choices are deliberately testable; polished output does not replace source evidence or a verified state transition.
